# サイクル001：APB書込みからUART波形まで

日付：2026-10-28 JST。目的は既存の小さなRTLを、第三者がPCで追試できる成果物にすること。
今回の範囲はローカル制作・シミュレーション・generic synthesis・記録まで。

## 1. 選んだ課題と候補

選択：**FIFOなしのAPB4 UART Txと、その固定回帰・波形デモ**。
FPGA／組込みを学ぶ人や小さなSoCを組む人が、レジスタ書込み・待機・UART出力を一続きで追試する作業を想定する。
これは課題仮説であり、実際の利用者への聞取り結果ではない。

既存の個人制作RTLと公開端子テストが見つかったため、新規設計より小さく再利用できた。
対照案は[verilog-uart](https://github.com/alexforencich/verilog-uart)などの既存UART、既存テストの手動実行、波形ビューアでの目視。
verilog-uartは同一APB仕様の比較品ではなく、READMEでは後継への移行が案内されている。

選ばなかった有力候補：

- VCD→UARTデコードCLI：具体的だが、任意VCDの時刻・名前・欠損・複数信号の解釈が必要で、既存RTLの再現より広い。
- CRCストリームIP：PCで検証できるが、今回は新しい多項式・反射・初期値・ハンドシェイクの仕様を増やさない。
- QEC／極低温制御向けIP：関心との接点はあるが、符号・データ・入出力と後段ハードウェア条件が未確定。

## 2. 事実・推論・事業仮説・unknown

- **事実**：既存UART RTLと6試験を取り込み、2試験を追加した。出所とSHA-256は[PROVENANCE](PROVENANCE.md)。
- **事実**：今回の実測条件・合否・ハッシュは[保存した検証記録](../reports/cycle_001/verification.json)。過去の検証結果を今回の結果として転記していない。
- **推論**：固定I/Oと既存参照モデルがあるので、仕様を変えずに1要因を比較しやすい。
- **事業仮説**：IP単体より、特定環境での検証・移植・小範囲の組込み支援が対価になる可能性もある。
- **unknown**：利用者、予算、支払意思、販売価格、実機性能、顧客受入、実際の市場差別化。

無料のUARTが存在することは代替手段の根拠であり、今回の成果物に購入需要がある根拠にはならない。

## 3. 成果物と実行

- 採用する基準RTL：`rtl/uart_tx_apb.v`。
- 比較RTL：`candidates/focused/uart_tx_apb.v`。
- 仕様と入出力：[README](../README.md)。32-bit APB4のDATA書込み1 byte→UART 8-N-1、LSB first。
- `make`：2案×7設定の固定回帰、不正設定拒否、短いA/Z波形、負例、証拠判定試験、利用可能ならgeneric synthesis。
- `make demo`：短いA/Z波形だけ。デモの合格を全検証の合格とは扱わない。
- 保存波形：[control](../reports/cycle_001/control/demo/dump.vcd)、[focused](../reports/cycle_001/focused/demo/dump.vcd)。

Python依存を入れた後は1コマンド。新たな有料API／サービスの呼出しは不要。
試験時刻・ツール版・全結果はJSON、各試験の詳細はXMLとログに残す。

## 4. 試験結果と未実施ゲート

最終実行は合格。固定回帰は8試験×7設定×2案の112件すべて合格、別モジュールの短いデモも各案1件合格。
不正パラメータは各案5組を拒否し、証拠判定の単体試験は5件合格。
意図的なD−1の誤りは、単なるプロセス終了コードではなく、`tx`と参照値の不一致を伴う失敗として検出する。

YosysではRTL既定値50 MHz／115200 baudを使用し、genericセルへの合成と構造検査を実施。
最終実行はcontrol=170、focused=158セル。第1回の完走と同じ条件・同じセル数で再現した。
この値は特定PDK／FPGAへのマッピング、面積、電力、Fmaxではない。

**未実施**：FPGA実機、配置配線、STA、CDC/RDC、DFT、形式検証、独立した外部の第三者による追試、顧客受入。
AIサブエージェントによるコードレビューと単体試験の別実行は行った。同じモデル設定のレビューであり、上記の外部検証を代替しない。
GitHub CIの定義は用意したが、GitHub上での実行は未実施。

## 5. 候補比較と失敗履歴

同一課題の2案に限定した。変更因子は分周カウンタの方向のみ。
controlは0→D−1の加算、focusedはD−1→0の減算。外部仕様と参照モデルは共通。
候補ID・プロンプト・モデル情報・費用・seedの記録は[candidates.json](candidates.json)と[生成指示](../prompts/candidate_generation_v1.md)。
正確な実行モデルID、生成seed、sampling設定、配賦費用は取得できず、unavailable／unknown。
Cocotb seed=0はテスト用で、モデル生成seedではない。adjacent／wildcardは未生成。

RTL候補に機能失敗は観測されなかった。減算案は機能とgenericセル数を比較する資料として残し、
基準RTLはcontrolのままとする。実デバイスの利点が未確認なので、セル数だけで置換を決めない。
意図的な負例は生成候補の失敗数に混ぜない。

実行系で実際に起きた失敗と対処：

1. デモの正規表現がモジュール名を含むテスト名に一致せず、全8件がskipになった。失敗記録は`reports/failures/01-filtered-out/`。
   デモを1試験の専用モジュールに変更。0件・欠落・skipを合格にしない単体試験を残した。
2. Cocotb 2.0.1のIcarus runnerが`-none`を付け、テスト合格でもVCDが生成されなかった。失敗記録は`reports/failures/02-no-waveform/`。
   ビルドには公式Python runner、実行には`vvp -vcd`を使う。ASCII VCDのヘッダと時刻も確認し、FSTを.vcdと誤認しない。
3. レビューでタイムアウト時に子のvvpが残る可能性を指摘された。プロセスグループ単位の終了へ変更し、
   実際に子プロセスを起動する回帰試験を追加した。これは観測したハングではなく、レビューで見つかった不備。

比較前後でRTLや試験を黙って差し替えないよう、実行は新規ディレクトリに分離し、ソースと実行系のハッシュを保存する。
最終一括実行は上記修正を含む版で完了した。保存JSONのソース／実行系ハッシュと現在のファイルの一致も確認済み。
