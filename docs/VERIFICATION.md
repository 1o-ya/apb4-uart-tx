# PC-only verification record

今回の目的は、第三者がソース・仕様・実行条件・失敗ログを確認し、FPGAなしで追試できることです。
公開してよい品質を単一の点数で表さず、確認した範囲と未実施の範囲を分けます。

## 実行コマンドと保存先

```sh
make demo       # 短いA/Z波形
make test       # quick profile
make verify     # full profile
make formal     # bounded SATだけ
make mutations  # 12種類の故障検出だけ
make unit       # 合否判定・プロセス管理だけ
```

すべてリポジトリのルートから実行します。準備とVS Code操作は[SIMULATION_JA.md](SIMULATION_JA.md)。
同じコマンドをホストと[Linuxコンテナ](CONTAINER.md)で使います。
各回は`reports/runs/`に新規ディレクトリを作り、`verification.json`、xUnit XML、ツールログ、必要な波形を保存します。
直近の全体状態は`reports/latest-qualification.json`。`profile`のquick/fullを必ず確認してください。

## 固定した試験条件

全体は両RTL候補を対象にする。RTL本体と外部仕様はサイクル001から不変で、テストと実行系を強化した。

1. **公開端子のサイクル参照モデル**：IcarusとVerilatorで8試験を同じ9設定で実行する。
   A/Zと全256byte、bit順、bit幅、STOP全期間、BUSY、連続書込みと待機、ストローブ、保護属性、
   不正アドレス／方向、送信中・待機中の非同期リセットを照合する。
2. **別の受信モデル**：TXの下降エッジからbit中心を標本化してbyteを復号し、受理したAPB書込み列と照合する。
   FSMの内部変数をコピーせず、DUT内部の信号も読まない。[STRESS_SPEC.md](STRESS_SPEC.md)に条件を定義した。
   両案×両シミュレータ×D=1/3/10×seed=1/20261028の24ケース。
3. **機能coverage**：全16ストローブ・全8PPROT・7種の不正アクセス・START/DATA/STOP reset・待機中resetを必須化。
   単なる操作回数ではなく、受信結果と待機・中断の整合も確認する。各ケースの`stress_coverage.json`を保存する。
4. **不正パラメータ**：clock=0/負値、baud=0/負値、baud>clockの5組を各案でコンパイル後に実行し、指定の`$fatal`を確認。
   コンパイル不成立やタイムアウトを正常な拒否と数えない。
5. **Mutation**：無変更の基準RTLが合格することを先に確認し、[12種類の単一故障](MUTATIONS.md)を検出できるか調べる。
   単なる非0終了ではなく、指定した名前付き試験のAssertionErrorを必要とする。
6. **有界形式検証**：両案×D=1/2/3を32/52/72クロックまでSATで検証する。
   任意の32-bitアドレス・データと保護属性を、合法APBマスター・初期resetの仮定の下で扱う。
   合計6証明に加え、送信完了・待機・エラーが到達可能な6証跡と、誤実装の反例を必要とする。
7. **HDL行coverage**：Verilatorの計測を有効にし、通常8試験と独立受信1試験を同じバイナリで実行する。
   各案の`coverage.dat`、LCOV `coverage.info`と未到達行を保存する。
8. **Lintとgeneric synthesis**：Verilatorの警告とYosysの構造検査を別の段階として記録する。

通常回帰の9設定は、1 MHzに対するbaud=1000000/500000/400000/300000/125000/100000、
50 MHz/115200、signed32-bitの最大clock=2147483647に対するbaud=2147483647/1073741824。
D=1/2/3/8/10/434と丸めの両側、分周計算の32-bit加算オーバーフロー境界を含む。
通常回帰は8試験×9設定×2シミュレータ×2案の288件。追加通信24件とcoverage用18件、短いデモ2件は別集計する。
故障入りの期待失敗や、参照復号器の合成データ自己試験を、通常RTLの合格件数へ足さない。

## 結果判定そのものを試す

`make unit`は期待するTestCase IDを実行前に取得し、実際に開始したID・件数・結果と照合する。
空discovery、重複／名前違い、欠落・破損したXML、skip、失敗、異常終了、未完了を合格にしない。
単体の`simulate.py`も新しいxUnit結果を確認し、シミュレータが終了コード0でもテスト失敗なら非0を返す。

タイムアウト／中断では対象プロセスの親子関係を調べ、別セッションへ移った子孫も停止する。
実プロセスを使う回帰で、無関係な兄弟プロセスを停止・終了しないことも確認する。
最初の観測より前に別セッション化と再親化を完了した任意のデーモンまで安全に帰属できるとは主張しない。
今回の管理対象は、自分で起動したコンパイラ・シミュレータ・検証スクリプト。

各実行の開始時と終了時で、RTL・テスト・スクリプト・固定仕様のハッシュを照合する。
実行中にコードが変わったときは、個々の試験が通っても全体を不合格とする。
履歴を上書きせず、成功していた古いXMLを新しい失敗の代わりに使わない。

## Lint除外とcoverageの読み方

Lintは`--Wall`を使用し、次の3分類だけを明示的に除外する。他の警告は失敗にする。

- `UNUSEDSIGNAL`：上流で保護するPPROT、未使用の上位データ／ストローブなど、仕様上使わない入力。
- `WIDTHEXPAND`：分周計算で64-bitの式に入る32-bit定数の拡張。
- `WIDTHTRUNC`：仕様上正のsigned32-bit範囲にある分周値から、integer／カウンタ幅への定数代入。

除外した分類が将来の新しい不具合を隠し得るため、RTLを変える場合は除外の妥当性も再レビューする。
今回のRTLは不変で、最大値・丸めのシミュレーションを併用する。除外ゼロのlint合格とは表現しない。

HDL行coverageは機能coverageや全条件／全分岐の証明ではない。未到達行を削除して率を上げない。
default状態回復の分岐など、通常の2-stateの合法状態遷移から到達しない行も、そのまま未到達として記録する。
Genericセル数は使用したYosys版と条件の結果であり、特定FPGA/ASICの面積・消費電力・Fmaxではない。

## 実際に起きた不備と回帰への反映

- 初回サイクルの全件skip・波形未生成は[サイクル001](CYCLE_001.md)に保存済み。
- VerilatorのGNU Makeが空白のある作業／依存パスを拒否した。ビルドを空白のない一時ディレクトリへ移し、
  Cocotbの実行ファイルにも一時エイリアスを作る。インストール済みライブラリは書き換えない。
- 2-stateの初期値0では`rst_n=0`の代入だけで下降エッジにならなかった。テストが1→0の実際のリセットを与えるよう修正。
- レビューで、0件のunittest、raw CLIの終了コード0、入れ子タイムアウト後の子孫残留、CIのquick実行を指摘された。
  期待IDの照合、raw CLIのXML照合、実プロセス回帰、CIの`make verify`指定で修正した。
- 最初の統合実行は、試験自体は合格したがレビュー中のコード変更をハッシュで検出し、全体を不合格とした。
  コードを固定した後の実行を最終結果とし、開発途中の結果と区別する。
- Linuxコンテナの最初の構築では`FlexLexer.h`が不足し失敗した。`libfl-dev`を追加し、再構築後に全検証を完走した。
- 配布ZIPを別フォルダへ展開した追試で、Darwinのプロセス終了処理が`EPERM`になる競合を検出した。
  停止済みのリーダーが生存している間に専用プロセスグループを終了し、その後に個々の子孫を終了する順序へ修正。
  シグナル順序の回帰を追加し、実プロセスの回帰と合わせて検証する。元の失敗ログは
  [ZIP追試の失敗記録](../reports/failures/cycle_002-extracted-cleanup/)に保存した。
